### 1. js/app.js:118 (리스너 js/app.js:85, :86)
- **증상**: 같이 정하기에서 메뉴 목록에 없는 후보(직접 적은 이름)로 돌아오면 메뉴 검색이 돌지 않아요. `openDecided` 는 top-level await 안(72줄)에서 `menuSearch.requestSubmit()` 을 부르는데, submit 리스너는 그 뒤 85·86줄에서야 붙어요. 리스너가 없으니 `preventDefault` 도 안 되어, 브라우저가 폼을 그대로 GET 으로 보내 `index.html?q=…` 로 다시 열고 menu·place·lat·lng 가 사라져요.
- **재현**: 메뉴 목록에 없는 이름으로 `index.html?menu=국수` 를 열어요(또는 vote.html 에서 직접 적은 후보로 정한 뒤 '근처 식당 보기'). 주소가 `index.html?q=국수` 로 바뀌고 결과 칸에는 슬롯만 남아요.
- **고칠 안**: `storeSearch`·`menuSearch` 의 `addEventListener` 를 메뉴를 불러오는 try 블록 앞으로 옮기거나, `openDecided` 에서 `requestSubmit` 대신 검색 함수를 바로 불러요. 시험 'menu 가 목록에 없으면 메뉴 검색으로 찾는다'를 더해요.

### 8. js/nearby-location.js:14 (부르는 곳 js/nearby.js:121)
